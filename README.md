# Wordmap analys

Локальная программа исследует семантику через официальные API Яндекса, хранит данные в SQLite и создаёт автономный HTML-отчёт.

## Запуск

1. Установите Node.js 22.
2. Выполните `npm install`.
3. Выполните `copy .env.example .env`.
4. Заполните в `.env` Yandex Cloud API key и Folder ID.
5. Измените `input.txt`.
6. Выполните `node main.mjs` (в Windows можно открыть `START.cmd`).
7. Откройте `results/<timestamp>/report.html`.

Проверка доступа к API: `npm run smoke`.

Ответ HTTP 429 программа пережидает сама. `Ctrl+C` безопасен: состояние сохраняется. Повторный `node main.mjs` продолжает незавершённое исследование с тем же `input.txt`.

## Входные сущности и релевантность

Обычная строка в `input.txt` является ручным seed-запросом. Директива `@brand Haoye` по-прежнему
создаёт дополнительные запросы бренда про топливную систему. Директива `@entity CUAV` только
добавляет сильный смысловой anchor: она полезна для производителей и моделей экосистемы, но сама
не создаёт топливные seed-запросы. Все `@brand` автоматически считаются также entities.

Wordstat-хвост целиком сохраняется в SQLite и CSV, однако рекурсивно обрабатываются только классы
`core` и `adjacent`. Классы `broad` и `noise` остаются видимыми в отчёте, не расходуя API-вызовы.
Автоматическая рекурсия ограничена восемью запросами на один root и 1000 запросами на run;
автоматический deep analysis — 300 наиболее приоритетными запросами. Ручные seeds не входят в эти
лимиты. Resume выполняется только при совпадении `input_hash` и версии алгоритма, поэтому старые
run-директории остаются нетронутыми после изменения логики анализа.

Уже собранный run можно безопасно переклассифицировать без новых запросов к API:
`npm run reclassify -- "results/<timestamp>"`. Перед первым изменением команда создаёт рядом файл
`research.before-reclassify.sqlite`, повторно его не перезаписывает, обновляет только решения
релевантности в рабочей БД и заново формирует CSV/HTML-отчёт.
